# End-to-end research and delivery roadmap

2 October 2026. Planning baseline: `caec37ef86a8b78e1eb88292ea6368bfb64bcbdc`.

## Executive decision

Develop a transparent, versioned **advisory simulator** around checked multipass replay, independently characterized material inputs, and measured force/torque/slip/gauge. Add fidelity only when a named output requires it and a benchmark can discriminate between alternatives. Keep scientific validation distinct from software verification, and keep a rendered machine distinct from a calibrated plant model.

The user leaves deployment options open. The recommended next engineering baseline is an offline, CPU-capable package with scenario/result files and a local viewer. This minimizes infrastructure dependencies while the science is qualified; it does not settle the eventual deployment target. All subsequent development must take place in the **saved Codex cloud environment**, after this research work. “Local” below describes where a future delivered advisory application could run, not a second development workspace. This task edits authored research documents only.

The present code has optional spatial hardening, tension-aware slab mechanics, circular Hitchcock contact, thermal ledgers and checked prescribed chains. It also has a narrow AA5052 gauge mesh search. It does not have calibrated foil/pack contact, predictive interpass cooling/annealing, thermal feedback to flow stress, calibrated mill-stretch/gauge closure or a general physically validated route optimiser. The separately published scheduler foundation `ef0996acdd7af1799c62cb9a2e628e35acd26206` is a candidate for later integration, not part of main. Uncommitted conditional-benchmark drafts reported by the parent are not published capability and must be recovered/reviewed before use.

## A state contract before a route search

At each pass, preserve three independent records:

* **Material state:** alloy/temper provenance, layer topology, gauge/width, accumulated geometric strain, effective hardening/internal variables, temperature/enthalpy, texture or residual field when the chosen model supports it, and uncertainty. Annealing does not undo total geometric reduction.
* **Equipment/configuration:** stand/roll stack, nominal and effective contact radii with distinct meanings, current coil radii, drive gearing, calibrated compliance, sensor locations and installed ratings with provenance.
* **Commands, observations and bounds:** requested gauge, speed/tension/cooling settings; separately measured signals with time/material coordinate/quality; independently established pass-local restrictions. Friction and material strength are model parameters, not freely adjustable actuators.

Each pass changes areas, strain, possible temperature, coil geometry and admissible limits. A constant stress gives a different axial force as gauge changes. A target gauge is not a screwdown command. Threading, established rolling, reversal, delay and tailout require distinct event states. A route evaluator must never infer an anneal, topology change, width trim, missing rating or temperature reset from a gauge alone.

One model tier need not solve every output. Mean force calibration cannot establish flatness, residual stress, fracture, thermal state, actuator dynamics or product fitness. GPU rendering does not establish GPU solver benefit. Profile actual workloads before selecting accelerated FE or surrogates; compare convergence and end-to-end cost, including data preparation.

## Phase P0 — Evidence closure and reproducible research baseline

**Goal:** make the corpus and current capability auditable. **Inputs:** immutable code baseline, original report, all code/document citations, topic reviews, parent benchmark audit, recovered source versions. **Method:** persistent work IDs with version/access records and requirement traceability; manual source semantics review plus generated reconciliation. Alternative: a reference manager may later replace files, provided IDs and provenance survive.

**Deliverables:** this indexed ledger, annotated reviews, approach comparison, implementation matrix, gap register and roadmap. **Dependencies:** no plant data needed. **Acceptance:** every observed citation mapped or explicitly unresolved; original 105 identities retained; JSON/CSV parse and counts reconcile; historical and current access separated; independent claim review completed. **Uncertainty:** unresolved bibliography cluster U001 and blocked full texts stay visible; no completeness claim for unseen history. **Gate:** source-specific equations/inputs cannot progress beyond their access level. **Risks/deferred:** source-count inflation, changed URLs and inaccessible books; recover exact book list before declaring historical library closure.

## Phase P1 — Numerical and semantic foundation

**Goal:** establish trustworthy calculations inside a declared domain. **Inputs:** checked replay, source/version-pinned equations, explicit SI adapters, current 86-test baseline, separate scheduler candidate. **Method:** retain pure-Python solver contracts and deterministic state evolution; compare independent quadrature, analytic limits and refinement. Alternatives: a different integrator/solver only after a failing case justifies it.

**Deliverables:** consolidated capability manifest; regression for midpoint thermal overshoot/global entropy; unit/state assertions; source-adapter parity checks; immutable replay artifacts. **Dependencies:** P0 equation traceability. **Acceptance:** valid/invalid/indeterminate statuses preserved; unmodelled discontinuous width/density/topology changes require named events; future continuous spread or temperature-dependent density requires an explicit constitutive model and mass balance; no arbitrary hardening resets; force/moment/mass/mechanical and thermal balances; refinement and domain-edge tests; positive heat capacity and physical finite-step thermal bounds in pure-exchange tests. The current 86 passing tests are a starting point, not this entire gate.

**Uncertainty:** numerical-error estimates and scenario sensitivity envelopes, explicitly not empirical confidence intervals. **Gate:** stop promotion if a source convention is silently chosen, a failed solver returns a ranked candidate, or thermal time refinement fails. **Risks/deferred:** circular contact validity, small-draft singularity, internal-neutral-point/sliding assumptions. No production parameters or physics upgrade is performed by this research task.

## Phase P2 — Conditional public benchmarks and parameter identifiability

**Goal:** learn where the present structure fails before fitting a richer model. **Inputs:** immutable R062 raw table, explicit adapters, R134 reserve, R007/R118 field/material leads. **Method:** run fixed-assumption no-fit comparisons first. Only then consider one global *effective initial-hardening parameter* fitted to pass-1 force if sensitivity/bracketing shows identifiability; this is not a measured prestrain. Preserve a no-fit reference. Alternatives: obtain independent initial flow curves; or postpone calibration when nonidentifiable.

**Deliverables:** raw/derived/assumed/predicted/observed separation; signed per-pass force and slip residuals; predeclared calibration/holdout contract; adapter-sensitivity report. **Dependencies:** P1; material/strain/stress mapping frozen before the new fit/comparison. All three published passes have already been inspected; later-pass checks are previously seen conditional comparisons, not pristine blind holdouts. **Acceptance:** every executable assumption equals its adapter record, pass IDs and state increments agree, m/mm–Pa/MPa adapters give equivalent canonical values, source Table 2 predictions are excluded from measured targets, and fixed friction is flagged for possible target reuse. Pass-1 slip remains a diagnostic; pass-2/3 holdout is a within-chain conditional check, not independent plant validation.

**Uncertainty:** no sensor errorbars are available; source ±5% is model discrepancy, not measurement uncertainty or an acceptance tolerance. Report conditional residuals and sensitivity; do not fabricate confidence coverage. **Gate:** freeze conventions before the new fit/comparison, report boundary fits/mismatch, stop if parameters compensate for unresolved units or conflicting outputs. **Risks/deferred:** source friction leakage, only three correlated passes; no thermal, torque, foil, safety or optimiser validation claim. Parent-reported uncommitted draft work must first pass recovery, review and executable-adapter parity tests in Codex cloud.

## Phase P3 — Independent measurements, calibration and offline validation

**Goal:** qualify a bounded aluminium use case. **Inputs:** selected alloy/temper/product, raw mechanical tests with orientation/rate/temperature, coil/pass genealogy; actual geometry/compliance; synchronized force, per-roll shaft torque, roll/strip speeds, gauge/tension and quality flags. **Method:** calibrate sensor zeros, load paths, drive losses and compliance independently; constrain material law from mechanical tests; then fit the smallest identifiable friction/contact parameter set jointly to force/torque/slip. Alternatives: controlled laboratory mill where plant access is unavailable; use source cases only for method qualification.

**Deliverables:** provenance-bearing material/contact/equipment cards; calibration report, grouped holdout set and domain map; observation operators with travel-coordinate alignment. **Dependencies:** P2 adapter discipline and approved data access. **Acceptance:** predefined error/coverage budgets for each required output; hold out whole coils/campaigns/grades appropriate to intended extrapolation; no adjacent-row leakage; test bias, heteroscedastic residuals and parameter correlations/profile likelihood; independent metrology review. Targets must be agreed before fitting from product tolerance and instrument uncertainty, not copied from a paper.

**Uncertainty:** separate measurement, parameter, numerical and structural error; propagate joint/correlated uncertainty. Demonstrate coverage on held-out groups where sample size supports it; otherwise label interval coverage unestablished. **Gate:** no calibrated production-domain claim until complete input provenance and independent holdout pass. **Risks/deferred:** force-only nonidentifiability, proprietary data rights and changing lubricant/roll conditions; missing torque/speed observations may require additional measurements rather than more model complexity.

## Phase P4 — Qualified multipass material and thermal history

**Goal:** predict state transitions that matter to the chosen route. **Inputs:** P3 cards, pass times/coiling delays, coolant circuits, temperatures, heat capacity/conductance data, anneal time–temperature histories and mechanical/microstructural observations. **Method:** conservative enthalpy/transport closure with verified time integration; add temperature/rate-dependent flow stress and recovery/recrystallization laws only within measured domains. Alternatives: measured boundary temperatures and documented externally supplied annealed states; sensitivity scenarios until kinetics are identified.

**Deliverables:** explicit interpass events and state uncertainty; thermal/history validation cases; model-form comparison between scalar hardening, dislocation-based and richer alloy-specific treatments. **Dependencies:** P1 thermal correction and P3 measurements. **Acceptance:** no heat double count; pure exchange obeys bounds and global entropy; timestep/material-coordinate convergence; independently measured thermal trajectories with observation location, material coordinate, time response and uncertainty, plus post-event flow curves; anneal reset justified by experiment. **Uncertainty:** calibrated ranges/parameter correlations; unknown heat partitions/contact coefficients remain scenarios. **Gate:** if thermal/history data cannot identify kinetics, keep supplied-event mode and prohibit predictive anneal optimisation. **Risks/deferred:** bright oily aluminium temperature metrology, radiation background, coil gradients and precipitation kinetics. R049 anneal reset and R138 fresh per-entry curves do not by themselves validate kinetics.

## Phase P5 — Scenario and constrained scheduling tools

**Goal:** compare admissible candidate routes with honest status and tradeoffs. **Inputs:** validated evaluator/state cards, required final product, explicit topology/events, pass-local operating choices and independently sourced ratings. **Method:** begin with the separately reviewed finite enumeration and full-route checked replay; later use pruning/DP/beam search only when state equivalence is justified. Compare NSGA-II or surrogate-assisted search for larger mixed/discrete domains against an exact small-grid oracle.

**Deliverables:** replayable candidate archive, rejected-edge reasons, Pareto/tradeoff report, rank provenance and sensitivity. **Dependencies:** P1 for synthetic algorithm studies; P3/P4 plus rating evidence for physical recommendations. **Acceptance:** enumerate a tractable oracle grid; rerun winners independently with stricter numerical settings; preserve failed, incomplete and indeterminate candidates; unknown constraints cannot yield 'feasible'; cache keys include history, equipment, model and data versions. Test ranking with omitted/partial limits. Respect the candidate branch's 'best within supplied choices' semantics.

**Uncertainty:** robust scenario checks or chance constraints only with defensible uncertainty models and agreed risk budgets; observed marginal min/max are not a valid joint operating region. **Gate:** energy/time objectives require coil mass/length, duration, idle/reversal/reel losses and efficiency; power sums are not energy. Stop recommendations outside support or with missing ratings. **Risks/deferred:** combinatorial cost, false optimality, friction treated as control, surrogate exploitation. Pack/noncircular/quality constraints enter only after their own P6 gates.

## Phase P6 — Output-specific higher fidelity and product quality

**Goal:** extend only the outputs required by the selected product. **Inputs:** foil/pack route data, roll-stack drawings/crowns/bending/shift maps, transverse gauge/flatness, cyclic material tests, damage and released-shape data. **Method:** independent work packages: noncircular/sticking and pack contact; mixed lubrication/surface; stack/profile/thermal crown; anisotropic/cyclic FE and release/damage. Alternatives: qualified offline FE for a few cases, with low-order envelopes for the interactive tool.

**Deliverables:** per-output validated modules and measurement operators, fidelity/cost map, clear unsupported statuses. **Dependencies:** P3 and relevant P4 state; specialist review. **Acceptance:** converge force and local fields separately; complementary stick/slip residuals and regularisation sensitivity with distinct aluminium-strip/roll elastic constants (R005 full form, not its steel equal-modulus shortcut); contact topology and interlayer balances; profile versus tensioned flatness versus unloaded shape measured separately; damage regularisation/objectivity and path tests. **Uncertainty:** field/parameter/model discrepancies propagated from upstream; mesh-refinement error not experimental truth. **Gate:** no single force fit validates these modules; retain guards until appropriate evidence passes. **Risks/deferred:** high compute, proprietary geometry and unavailable field data. R108/R109 offer texture/history comparisons subject to table/extraction/raw-data gates; post-pass coil-surface temperatures in R108 are not in-bite trajectories; features unneeded by the initial product remain deferred rather than blocking a narrower advisory release.

## Phase P7 — Usable scenario UI and 3D digital-twin presentation

**Goal:** make qualified results understandable and reproducible. **Inputs:** stable solver/result schema, capability/status metadata, scene IDs, user workflows. **Method:** thin UI calling the tested solver with editable scenarios, side-by-side observations/predictions, uncertainties and failed-case explanations; Blender/USD consume results. Alternatives: CLI + static report first, browser/local desktop later; optional Kit-CAE only after a measured visualization requirement and licence/hardware assessment.

**Deliverables:** scenario editor, pass/state timeline, source/assumption inspector, comparison plots and linked 3D playback. **Dependencies:** P1 schema; P3 for empirical labels; P5 for scheduler views. **Acceptance:** unit labels, accessibility/keyboard checks, numerical/visual parity, true gauge or labelled visual exaggeration, no invented stress/temperature colours, warning visibility, cancellation/error recovery and saved-run replay. **Uncertainty:** ranges and missing evidence remain visible; unsupported quantities cannot appear as measured outputs. **Gate:** users can distinguish settings, sensors, predictions and bounds without inspecting source code. **Risks/deferred:** convincing visuals overstating accuracy; live animation and heavy GPU dependencies are optional. No machine connection is part of this phase.

## Phase P8 — Packaging, reproducibility and release engineering

**Goal:** deliver an installable, supportable advisory build. **Inputs:** selected target OS/hardware/offline needs, approved runtime/model/data versions, licensed dependencies, representative workloads. **Method:** build and verify in Codex cloud; export a pinned package/container/installer appropriate to the chosen target. Keep pure solver independent of renderer. Alternative formats are chosen after deployment decision D03, not guessed now.

**Deliverables:** locked dependencies and hashes, software/material/data bill of materials, provenance manifest, reproducible fixtures, migration/backup/rollback and operator guide. **Dependencies:** qualified subset P1–P7 and user target decision. **Acceptance:** clean-environment offline installation/replay, no hidden network or secret dependency, package integrity, version compatibility, malformed-file limits, performance/memory budget on target hardware, restore/rollback drill. Optional Blender/OpenUSD checks need installed compatible runtimes; the current audit's missing `pxr` is not a successful USD runtime check.

**Uncertainty:** timing and resource claims measured on declared workloads/hardware; no unsupported GPU promise. **Gate:** release only the qualified capability subset and reproduce a saved result from immutable inputs. **Risks/deferred:** binary/runtime portability, external software licences, serialized-model trust. Secure dependency installation can use official hash-checking practice R144; this does not certify the application secure.

## Phase P9 — Offline/advisory deployment and operational observation

**Goal:** place the chosen advisory release with its intended users. **Inputs:** approved deployment architecture, data ownership/access rules, support owner, monitoring thresholds and retention policy. **Method:** staged installation → historical replay → supervised advisory evaluation. Options: local desktop/offline files; edge read-only replay/near-line advice; shared on-premises service with authentication and job isolation. **Deliverables:** runbooks, access model, audit logs, signed/reviewed model releases, drift/quality dashboard and rollback.

**Dependencies:** P8 plus explicit deployment authorization. **Acceptance:** no control write path; log run/input/model/calibration versions, solver residuals, domain violations, missing/late sensors, latency and uncertainty; test loss of data/network, stale clocks, malformed uploads, full storage, backup restoration and rollback. Human reviewers can reject advice and reproduce why it was given.

**Uncertainty:** drift alarms distinguish instrumentation/calibration change from material/process shift; a successful run is not evidence of physical accuracy. **Gate:** revert to replay-only or suppress advice when inputs are stale/out of domain, calibrated uncertainty is invalid, a required rating is missing, or validation expires. **Risks/deferred:** data exfiltration, insecure imports, unreviewed updates, misleading stale results. R143 is an OT-security planning reference; the full site security programme must be tailored by responsible experts.

## Phase P10 — Eventual plant advisory integration

**Goal:** evaluate advice with real operational context without controlling equipment. **Inputs:** approved read-only historian/data interfaces, signal dictionary, synchronization and quality records, plant experts and evaluation design. **Method:** shadow mode before human-reviewed recommendations; retain existing plant controls and operational procedures. Alternatives: periodic exported-data batches when live data access is not justified.

**Deliverables:** read-only ingestion adapter, shift/campaign evaluation, operator feedback, drift investigation and documented benefit/quality tradeoffs. **Dependencies:** P3/P9 site-specific validation and authorization. **Acceptance:** material-coordinate alignment across acceleration/reversal, stale/missing/bad-sensor suppression, no leakage from future measurements into schedule-time predictions, prospective evaluation predeclared with confounders documented. **Uncertainty:** operator actions and campaign changes confound observational benefit; distinguish model-evaluated savings from observed plant outcomes. **Gate:** plant engineering, operations, IT/OT security and data owner accept the bounded advisory use. **Risks/deferred:** integration latency, changing recipes and automation bias; no promised energy/productivity percentage.

## Separate programme — live closed-loop industrial control

Live control is **not** an endpoint authorized by this task or an automatic next release. If ever requested, it requires a distinct safety and controls programme: hazard/risk analysis, control/stability and actuator dynamics, fail-safe/fallback design, independent interlocks, timing and communication assurance, simulation/hardware-in-loop testing, controlled commissioning, management of change, responsible engineering signoff and explicit operating authorization. Applicable site standards and regulatory requirements must be determined by qualified owners. An advisory model's validation, unit tests or security review cannot substitute for that programme. The agent will not operate equipment.
